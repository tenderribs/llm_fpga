# CPU subsystem (MicroBlaze V block design)

Generated by `scripts/gen_cpu.tcl` (`make cpu`, which runs automatically
for `TOP=top_soc`) into `build/cpu_bd/`. `top_soc.sv` instantiates it as
`u_cpu`.

## Contents

| Block | Configuration |
|---|---|
| MicroBlaze V (`mbv`) | RV32IMF: single-precision FPU, hardware multiply and divide. `C_OPTIMIZATION 0`: 5-stage performance pipeline, branch target cache |
| Instruction cache | 8 KB, over DDR3 `0x8000_0000`-`0x9FFF_FFFF` (unused: the code runs from local memory) |
| Data cache | 32 KB, write-back, 16-word (64-byte) lines, one line-wide AXI transfer per miss, same range |
| Local memory | 256 KB of LMB block RAM (64 RAMB36): code, data, stack |
| Second data LMB | `Y_BRAM` port out to `llm_core`'s Y / V RAMs |
| Debug module (`mdm`) | JTAG debug: load and run firmware with `xsdb` |
| Clocking wizard | 150 MHz CPU clock from the 225 MHz `clk` input |
| `proc_sys_reset` | resets for the CPU clock domain |
| SmartConnect (`sc`) | 4 slaves, 2 masters, 2 clocks; see below |

**Why 150 MHz.** The MicroBlaze V's pipeline doesn't close timing at
225 MHz on this part, so the CPU runs at 150 MHz on its own clock. See
[system_design.md](../system_design.md#4-clocks-resets-and-clock-domain-crossings).

**The data cache is write-back.** Nothing else reads what the CPU writes
to cached DDR3: the engine only reads weights, which the CPU never writes.
The KV cache is written by DMA and read by the attention unit; the CPU
reaches that region only uncached.

## Address map

These are the CPU's addresses. `S_AXI_EXT` (`llm_core`'s master) sees DDR3
at the same place.

| Address | Size | What | Reached through |
|---|---|---|---|
| `0x0000_0000` | 256 KB | local memory | instruction and data LMB |
| `0x0010_0000` | 256 KB window | `llm_core`'s Y RAM (128 KB, read only); V RAM at `0x0012_0000` (32 KB, read and write) | second data LMB (`Y_BRAM`) |
| `0x4000_0000` | 256 KB | `llm_core` registers | `M_AXI_PERIPH` (AXI4-Lite), uncached |
| `0x8000_0000` | 512 MB | DDR3, cached | data and instruction caches → SmartConnect → `M_AXI_DDR` |
| `0xA000_0000` | 512 MB | DDR3, uncached (the KV cache) | the CPU's peripheral port → SmartConnect |

The cached range has to be a power of two. That is why only the lower
512 MB is cached and the upper half is reached uncached.

## External ports

| Port | Type | Clock | Connects to |
|---|---|---|---|
| `clk`, `resetn` | input | 225 MHz | `ui_clk` and the DDR controller's reset |
| `S_AXI_EXT` | AXI4 slave, 256-bit | 225 MHz | `llm_core`'s DDR3 master (DDR3 at `0x8000_0000` in its view; `top_soc` adds the offset) |
| `M_AXI_DDR` | AXI4 master, 256-bit | 225 MHz | the DDR3 controller |
| `M_AXI_PERIPH` | AXI4-Lite master, 32-bit | 225 MHz | `llm_core`'s registers |
| `Y_BRAM` | block RAM port | CPU clock (brought out as `Y_BRAM_clk`) | `llm_core`'s `yb_*` port |

`S_AXI_EXT` allows 8 outstanding reads and 16 outstanding writes, so the
weight reader's 8 bursts and the DMA's 15 writes are all in flight at once.

## Costs measured with `fw/build/membench.elf`

| Access | Cost |
|---|---|
| Local memory | single cycle |
| Y / V RAM over the LMB | a few cycles |
| A register access through the SmartConnect (crossing and AXI4-Lite) | about 37 CPU cycles |
| A D-cache miss (one 64-byte line) | a few dozen cycles |

That is why:
- hot buffers live in local memory (`fast_calloc`);
- results come back over the LMB;
- each job costs a handful of register accesses (about 300 jobs per
  token).

## FPU notes (`fw/build/fpubench.elf`)

- The FPU is pipelined. A dependent chain of adds is much slower than
  independent ones.
- Float add latency is about 6 cycles. That is why RMSNorm's sequential sum
  of squares (0.6 ms per token) can't be sped up without changing the bits.
- The firmware overlaps independent float work four elements at a time.
- Division and square root are long-latency instructions.
- `fcvt.w.s` with the `rmm` rounding mode rounds half away from zero in one
  instruction. Quantize uses it.
- The startup code (`fw/common/start.S`) enables the FPU (`mstatus.FS`)
  and sets round-to-nearest-even.
